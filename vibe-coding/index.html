SpectrumVibe coding is geen aan/uit-knop maar een schuifje. Van links (AI vult je regel aan) naar rechts (je schrijft zelf geen code meer). Het verschil met "AI-tools voor developers": bij een agent geef je een doel, geen instructie. Die leest zelf de code, draait tests en levert een pull request op.

Security & privacy

Kwaliteit is afgedwongen, niet gehoopt

  • Local-first: gezondheidsdata blijft op de telefoon. API-keys in de iOS Keychain, niet in de code.
  • Bring your own key: de gebruiker kiest Gemini, OpenAI, Claude of Mistral.
  • Elke PR door dezelfde poort, juist die van de agent: SwiftLint, tests, CodeQL.
  • Games & RPG: geheimen nooit in GitHub, achter Cloudflare Access.

Wat ik geleerd heb

01

Snel bouwen is verslavend en goedkoop

Een prototype kost een avond. Weggooien en opnieuw beginnen is geen verspilling meer. Het endorfineshotje na elke prompt is echt, en dat is ook een risico: je bouwt sneller dan je nadenkt.

→ bouwen is niet meer schaars
02

Modellen worden elke paar maanden beter

Van een chatbot die ik moest voorzeggen (maart) naar een agent die een epic zelfstandig oplevert (oktober). Wat vandaag niet lukt, lukt misschien over drie maanden. Een training is verouderd voordat hij af is.

→ leer door te doen
03

Samenwerken verschuift naar beslissen

Met zes mensen is de agent nooit de bottleneck. Afstemming, smaak, prioriteit en testen wel. Issues worden de interface tussen mens en agent.

→ de PO-rol wordt belangrijker
04 · Drie learnings · ~2 minDrie dingen. Eén: bouwen is niet meer schaars, dus je kunt experimenteren. Twee: de snelheid van verbetering is absurd. Wat ik in maart deed (copy-paste tussen chatbots) is nu al ouderwets. Drie: hoe meer mensen, hoe duidelijker dat de mens de bottleneck is.

Drie vragen voor Alliander

Developers bij Digital Delivery

  • Van code schrijven naar agents regisseren, reviewen en architectuur bewaken
  • Spelregels (CLAUDE.md), tests en pijplijnen worden het echte vakmanschap
  • Juniors leren anders. Hoe word je senior zonder het zware werk?

Wat doe jij morgen niet meer zelf?

Scrum-teams

  • Een sprint van twee weken voelt traag als een epic in één nacht af is
  • De PO en de tester worden de bottleneck, niet de developer
  • Refinement wordt specificeren voor agents: acceptatiecriteria zijn weer goud

Hoe groot is een team als agents meedraaien?

Change Delivery

  • Meer en kleinere changes, sneller: governance moet meeschalen
  • Afdwingen in de pijplijn in plaats van in een CAB-overleg
  • Wie is eigenaar van code die niemand geschreven heeft?
